## 4. Content accuracy

**Outside facts (checked 4 October 2026, linked in Sources):** Google Forms has no equation editor; EquatIO inserts maths as images (Texthelp). Microsoft Forms: Math switch with equation editor and keypad, suggests options, Microsoft 365 (Microsoft Support). Neither has negative marking built in (Microsoft Q&A; Google needs an add-on); Microsoft Forms can't take a range as a quiz answer (Microsoft Q&A); Google grades short answers by exact text. KaTeX outputs HTML + MathML. Exam patterns: JEE Main Maths 20 MCQ + 5 numerical at +4/−1 (linked to the JEE guide), SSC CGL quant 25 × +2/−0.5, IBPS PO prelims quant 35 in 20 min at −0.25.

**Measured:** quadratic formula as LaTeX = 41 bytes; its 1× screenshot (`public/guides/math-test-maker/quadratic-screenshot.png`) = 2,620 bytes (≈64×).

**Product claims:** listed in the header comment of `src/guides/mathTestMaker.ts`. Not claimed: step marking, expression or fraction answers, a graphing tool, printing a test as a paper.

**Answers:** every question in `src/guides/mathData.ts` has its working in a comment.

## 5. Product fix shipped with this guide: "Exact value(s)" numerical answers

The builder offers **A range of values** or **Exact value(s)** for a numerical question. In exact mode, `min`/`max` stay at their 0 defaults, but every scorer except `results.py` read only `min`/`max`, so a correct answer (e.g. 150 for "100, 150, 200") was marked **wrong** by the server (`scoring.py`, used for link submissions and sittings), the exam screen, history and solutions.

| File | Change |
|---|---|
| `backend/app/services/scoring.py` | `score_question` honours `exactMatch` + comma-separated `exactAnswers` |
| `frontend/src/utils/numericalAnswer.ts` (new) | `isNumericalCorrect`, same rule, used by TestPage (×2), SolutionsViewPage, TestHistory (×2) and the guide's demos |
| `backend/tests/test_numerical_scoring.py` (new) | 4 tests (range, exact with 0 defaults, junk entries, exactMatch false) |

Live data (4 Oct): 1,171 numerical questions, all saved as ranges; **none** use exact mode yet, so the fix changes no existing result.
